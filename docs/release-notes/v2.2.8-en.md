# CPA Manager Plus v2.2.8

> [中文 ->](https://github.com/tcatarina/CPA-Manager-Plus/blob/v2.2.8/docs/release-notes/v2.2.8-zh.md)

## Overview

Sync the fork with upstream v1.14.8 and v1.14.9, including dependency security maintenance and credential/quota presentation fixes. Preserve the fork's GLM support, updater repository, and Linux/macOS native packages.

## Fixes

- Keep credential history, quota usage, analytics, and model-price rows visible during same-scope background refreshes and temporary failures.
- Invalidate historical evidence when credential identity changes without discarding unaffected rows.
- Resolve ambiguous monitoring sources using the event provider and preserve configured upstream labels.
- Display additional Antigravity quota windows and distinguish confirmed-empty usage from unknown or stale data.
- Improve xAI subscription-plan recognition and retain observed quota when subscription lookups fail.

## Security and Build Maintenance

- Adopt upstream's patched Go/Node toolchains and application, documentation, and build dependencies.
- Require npm dependency audits and cross-platform Go vulnerability checks in CI.
- Update the transitive development dependency Zod to 4.6.7 to address the additional advisory found while validating this sync.

## Validation

- Frontend: 4,525 tests passed; type checking, production build, and documentation build passed.
- Manager Server: 2,848 Go tests passed; vet and vulnerability scan passed.
- npm audit reported zero known vulnerabilities at validation time.
- Local runtime smoke test used the production web build, a separate SQLite database, and an isolated local CPA: setup/login, navigation, credential refresh and layout switching, GLM drawer rendering, usage import/readback, restart persistence, and authentication rejection passed without browser exceptions.
- Two unchanged installer fixture tests could not pass on the NixOS host because they invoke missing `/bin/rm` and `/bin/mv`; the merged commit's GitHub PR Check completed successfully on its Linux runner.

## Upgrade Notes

No database migration, credential recreation, or configuration rewrite is required. No VPS deployment is part of this release preparation. Source builds require Go 1.26.10 and a Node.js version satisfying the repository's engines constraint.

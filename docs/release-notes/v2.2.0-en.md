# CPA Manager Plus v2.2.0

[中文](https://github.com/tcatarina/CPA-Manager-Plus/blob/v2.2.0/docs/release-notes/v2.2.0-zh.md)

## Upstream sync

Syncs the stable fixes published upstream in v1.14.2.

- **CPA v8 client API keys.** API keys are read from the `access.api-keys` layout introduced by CPA v8, alongside the existing layouts. Previously a v8 config could present as having no client keys.
- **Pricing rebuild after usage cleanup.** Historical usage maintenance deletes archived rows. Model pricing is now rebuilt from the retained events instead of being marked unrecoverable, so the model-price and monitoring syncs converge again.
- **Account history degradation.** When a cost cannot be rebuilt for one account, that account's requests, tokens, and success rate stay available and only the cost column shows as unknown.

Pricing recovery is scoped per account, so a single unrecoverable account no longer blocks the rebuild for every other account. Coverage errors are classified separately from verifier system errors, and SQLite busy contention no longer discards derived state.

## Fork behaviour

Unchanged from v2.1.0:

- GLM credential details use the shared five-tab drawer with quota, settings, models, diagnostics, and reset-card redemption.
- Dashboard CPAMP release links point at `tcatarina/CPA-Manager-Plus`. CLIProxyAPI release links are unchanged.

## Compatibility and upgrade

No database migration or credential migration is required. Existing GLM keys remain in CPA's OpenAI-compatible provider configuration.

Requires CPA v7.3.4 or newer. Native packages target Linux and macOS on amd64 and arm64. Windows packages are not published.
